# 存量业务调研规范

本文件用于步骤 4/6：当本次范围涉及已有接口改造、扩展或对接时，先调研真实代码，再写技术分析。

## 触发条件

满足任一条件即触发：

- PRD 或任务拆分明确说“改造”“复用”“对接”“兼容”已有接口。
- 本次流程依赖已有表、已有状态机、已有消息、已有定时任务。
- 新接口需要与已有业务流程共享数据或状态。
- 用户提供了存量接口、项目、模块或代码路径。
- 技术分析需要判断“会不会影响已有调用方”。

不涉及存量业务时，在决策记录中写明“本次为新建能力，不触发存量调研”。

## 向用户收集的信息

| 信息 | 示例 |
|---|---|
| 存量接口名称 | `POST /order/pay/callback` |
| 代码位置 | `backend/.../OrderCallbackController.java` |
| 所属项目/模块 | `storemate-merchant-service-web` |
| 调用方或上下游 | 第三方回调、客户端、内部服务、MQ |
| 用户关注点 | 兼容老数据、避免影响旧流程、复用状态机 |

用户无法提供完整代码位置时，先用 `rg` 在仓库中搜索接口路径、类名、表名或关键业务词。

## 调研执行

优先使用 subagent 调研；若当前环境没有可用 subagent，则主 Agent 自行完成同样的调研。

调研必须基于真实代码和真实表结构，不能只读接口文档后推测。

调研范围：

- Controller/RPC/MQ/Job 入口。
- Service/Manager 核心业务逻辑。
- Repository/Mapper/XML/Entity 数据访问。
- 外部服务调用、消息发送、定时任务、事务注解。
- 相关表结构和索引。
- 上游调用方和下游依赖。

## 技术分析引用方式

技术分析文档中需要引用调研结论：

- 在概览或已有系统集成章节说明调研对象。
- 在核心流程中引用存量接口的事务、幂等、状态流转约束。
- 在风险章节写明兼容性风险和兜底。
- 在 `decision-log.md` 中记录调研结论对方案的影响。
